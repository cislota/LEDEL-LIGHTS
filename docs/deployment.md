# Развёртывание

Текущая конфигурация рассчитана прежде всего на локальный запуск. Перед публикацией нужно отдельно проверить безопасность, хранение секретов и восстановление данных.

## Nginx

Docker Compose использует `nginx/nginx-dev.conf` без HTTPS.

- `/` направляется во frontend;
- `/api/` и `/docs` направляются в FastAPI;
- `/admin/sql` направляется в SQLAdmin;
- `/admin` направляется во frontend-панель.

Production-конфигурация с HTTPS находится в `nginx/nginx.conf`. Подробная инструкция: [nginx/ssl/README.md](../nginx/ssl/README.md).

## Перед публикацией

1. Задайте уникальные значения всех секретов.
2. Ограничьте CORS реальными доменами.
3. Настройте TLS-сертификат и production-конфигурацию Nginx.
4. Закройте прямой внешний доступ к PostgreSQL и служебным портам.
5. Проверьте защиту всех административных маршрутов.
6. Примените миграции Alembic.
7. Создайте и проверьте резервную копию.
8. Выполните health-check и изучите журналы сервисов.

## Резервные копии

Скрипты находятся в `scripts/` и работают с PostgreSQL в Docker Compose.

- `scripts/backup.ps1` и `scripts/backup.sh` создают архив;
- `scripts/restore.ps1` и `scripts/restore.sh` восстанавливают базу;
- срок хранения задаётся через `BACKUP_RETENTION_DAYS`.

Полная инструкция: [scripts/README.md](../scripts/README.md).

Резервные копии могут содержать контактные данные клиентов. Не добавляйте их в Git и храните в защищённом месте.
