# LEDEL-LIGHTS: инструкции репозитория

## Структура проекта

- `frontend/` — Next.js, React, TypeScript и Tailwind CSS.
- `backend/` — приложение FastAPI.
- `backend/routers/` — HTTP-маршруты и обработка запросов.
- `backend/services/` — бизнес-логика, фоновые задачи и внешние интеграции.
- `backend/models/` — модели SQLAlchemy.
- `backend/schemas.py` — Pydantic-схемы API.
- `backend/alembic/` — миграции базы данных.
- `nginx/` — конфигурация reverse proxy.
- `docker-compose.yml` — локальный запуск PostgreSQL, backend, frontend и Nginx.

## Правила внесения изменений

- Не включай в задачу несвязанные правки и форматирование посторонних файлов.
- Сохраняй существующие публичные API-маршруты, если задача явно не меняет контракт.
- Оставляй обработку HTTP-запросов в `backend/routers/`, а бизнес-логику и интеграции — в `backend/services/`.
- При изменении структуры данных согласуй модели SQLAlchemy, Pydantic-схемы и миграции Alembic во всех затронутых местах.
- Сохраняй идемпотентность синхронизации: повторная обработка одинаковых данных не должна создавать дубликаты.
- Не заменяй существующий стек и не добавляй production-зависимости без необходимости, связанной с задачей.
- Не добавляй в репозиторий `.env`, `.env.local`, токены, пароли, необработанные production-ответы, кеши и результаты сборки.
- Для проверки синхронизации используй обезличенные локальные фикстуры. Не обращайся к production API Tilda без явного требования.

## Проверка изменений

Выполняй проверки только для затронутых частей проекта.

Для frontend:

- `npm run lint` в `frontend/`;
- `npm run build` в `frontend/`.

Для backend и инфраструктуры:

- `docker compose config`;
- сборка затронутых сервисов;
- запуск затронутых сервисов;
- проверка `GET /api/health`;
- просмотр журналов backend на наличие ошибок запуска и выполнения.

Если меняется структура базы данных, создай миграцию Alembic и проверь применение актуальной цепочки миграций на локальной тестовой базе.

Не отмечай проверку как успешную, если команда не запускалась или завершилась ошибкой. Если проверку нельзя выполнить в текущем окружении, укажи причину.

## Результат работы

После выполнения задачи сообщи:

- что изменено;
- какие файлы затронуты;
- изменились ли API-контракт или структура базы данных;
- какие команды и проверки выполнены;
- какие ограничения или риски остались.
